ATTACK AND ISOLATION

Changing an object reference

The vulnerable path uses the submitted proposal ID to read one of two synthetic proposals but intentionally skips the comparison between that proposal’s freelancer and the authenticated requester. In vulnerable mode, Freelancer A can read Freelancer B’s bounded fixture proposal.

The vulnerable path is read-only, limited to this fixture allowlist, and is reachable only when the stored mode, explicit lab-enable flag, nonproduction environment, loopback peer, and local-host request gate all permit it. It never changes the normal marketplace proposal route.

MITIGATION

Authorize every object against the session user

Mitigated mode derives the requester from the authenticated server-side session and checks that the selected proposal belongs to that user. The requester ID is never accepted from the form. A cross-user lab request receives HTTP 403 with no proposal contents; a request for the user’s own proposal remains available.

Normal marketplace proposal pages always keep their existing object-level authorization checks in either lab mode. The demonstration does not alter or bypass them.
