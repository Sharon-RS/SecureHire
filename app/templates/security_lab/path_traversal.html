Path Traversal

In freelance marketplaces, applications frequently display contract templates, platform guidelines, and invoice summaries. If an application constructs file paths from user input without canonicalization and containment verification, attackers can supply directory traversal sequences (such as ../ or ..\) to escape the intended directory and read sensitive files across the filesystem.

Effective mode: {{ state.effective_mode|upper }} Protection: {{ state.protection_status }}

ATTACK FLOW

How directory traversal breaches filesystem boundaries

  1. An application accepts a filename parameter (e.g. ?doc=freelancer_guidelines.txt) to display files from an intended folder (public/).
  2. An attacker supplies traversal sequences (e.g. ../restricted/synthetic_server_config.ini or ..\restricted\confidential_contract.txt).
  3. Without canonical resolution and boundary checks, naive path concatenation resolves outside the allowed subfolder.
  4. The server opens and returns internal server configuration files, credentials, or proprietary documents to the attacker.

MITIGATION

Four pillars of secure path traversal defense

  • 1. Canonical Path Resolution: Never rely on string-matching or naive prefix checks. Normalize and resolve the path using Path.resolve() or os.path.realpath() to collapse all symbolic links, relative references (.., .), and redundant separators.
  • 2. Strict Containment Verification: Verify that the resolved target is strictly contained inside the designated root directory: resolved_target.is_relative_to(allowed_root) (Python 3.9+). If the target does not share the allowed root prefix, immediately reject the request.
  • 3. Indirect Object Identifiers: In production web applications, avoid exposing filesystem paths in query parameters or forms. Instead, use an opaque identifier (e.g. database ID or key in an allowlisted dictionary) that maps server-side to an authorized file location.
  • 4. Windows-Specific Path Defenses: On Windows platforms, defend against backslash separators (..\), drive letters (C:\), UNC shares (\\server\share), Alternate Data Streams (::$DATA), and trailing dots/spaces.
